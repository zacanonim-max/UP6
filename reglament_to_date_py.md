# Регламент технического обслуживания утилиты «Калькулятор дней между датами» (date.py)

## 1. Паспортная часть и общие положения

### 1.1. Паспорт документа

| Параметр | Значение |
|---|---|
| Наименование системы | Утилита командной строки `date.py` — вычисление количества дней между двумя датами с учётом високосных лет |
| Тип системы | Консольное приложение (CLI) на Python 3 |
| Зависимости | Только стандартная библиотека Python: `sys`, `os`, `argparse`, `datetime` |
| Формат входных данных | Две даты в формате `ДД.ММ.ГГГГ`, каждая на отдельной строке |
| Режимы ввода/вывода | Консоль (интерактивно) или файлы (`--in FILE`, `--out FILE`) |
| Кодировка файлов | UTF-8 |
| Коды возврата | `0` — успех; `1` — ошибка данных или ввода-вывода; `2` — входной файл не найден |
| Версия документа | 1.0 |
| Статус | Действующий |

### 1.2. Назначение документа

Регламент устанавливает порядок, периодичность и содержание работ по техническому обслуживанию (ТО) утилиты `date.py`. Цели внедрения регламента:

- обеспечить корректность расчётов: ошибка в определении високосного года или длины месяца напрямую искажает результат;
- минимизировать простои и сбои при запуске утилиты (несовместимость версии интерпретатора, недоступность файлов, проблемы кодировки);
- обеспечить предсказуемое поведение при некорректном вводе: понятное сообщение об ошибке и корректный код возврата;
- сохранить работоспособность утилиты при обновлении среды выполнения (Python, ОС);
- зафиксировать зоны ответственности и порядок действий при инцидентах.

### 1.3. Область применения

Регламент распространяется на:

**Программное обеспечение**

- файл `date.py` и его функции: `is_leap_year`, `days_in_month`, `parse_date`, `days_between`, `calculate`, `read_console`, `write_console`, `read_file`, `write_file`, `build_parser`, `main`;
- интерпретатор Python 3 на рабочих местах и серверах, где запускается утилита;
- сценарии, пакетные файлы и задания планировщика, вызывающие `date.py`.

**Аппаратное обеспечение и среда**

- рабочие станции и серверы, на которых установлена утилита;
- файловые каталоги с входными и выходными файлами (`--in`, `--out`).

**Не входит в область применения:** разработка нового функционала (форматы дат, новые режимы работы) — выполняется в рамках отдельного процесса разработки и сопровождения.


2. Выполнить: `python date.py --in test_in.txt --out test_out.txt`.

### 3.2. Порядок контроля

1. Ответственный за ТО фиксирует каждую выполненную операцию, указывая дату, исполнителя, результат и отклонения.
2. Проверяющий не реже одного раза в квартал выборочно перепроверяет выполнение карт и достоверность записей.
3. Результаты метрик анализируются ежеквартально; при выходе значений за целевые принимаются корректирующие меры.
4. Любое изменение кода `date.py` сопровождается регрессионной проверкой (ППР-04) и обновлением эталонной хэш-суммы.

### 3.3. Перечень документов отчётности

По результатам ТО ведутся следующие документы (шаблоны в настоящем регламенте не приводятся):

- акты технического состояния утилиты;
- отчёты о сбоях (инцидентах).

Сроки хранения и порядок передачи документов определяются внутренними правилами организации.
